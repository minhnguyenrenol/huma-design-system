Huma design system

The language of the Huma wallet: sending, exchanging and giving to Humanity Centres. It aims to make a money action feel calm, without hiding the numbers.

Shared for portfolio review. This is Unera's product, which is designed and not yet launched. Designed by Minh Nguyen as Lead Product Designer. Please don't reuse it. This public copy uses Hanken Grotesk in place of the licensed brand font, and sample figures replace real ones.

How it decides

These are the four rules the tokens and components follow.

  • Clarity before decoration

    Type, spacing and colour say what matters before the words do. People should be able to scan a wallet without reading it.

  • Trust through restraint

    Deep Blue chrome, solid fills and the same card shape everywhere. Product UI has no gradients.

  • Money has a direction

    Green and red mean money in and out. They are never used for decoration, and they always come with a sign or an icon.

  • Accessibility is the floor

    Visible focus, 44px targets, reduced motion, AA contrast. These are part of the tokens, not a polish pass.

What the v2.1 audit found

I checked tokens, contrast, docs and rendering with scripts, then compared before and after screenshots.

The product pages never loaded the system. 41 of 43 pages kept their own copy of the tokens in :root1,533 copied declarations
12 tokens had different values on different pages. For example, --font-stat-size was 1.5rem on one page and 2.5rem in the system12 tokens
--gradient-* means a gradient in the brand guide and a solid fill in the product. Pages override it to solid39 pages
Hard-coded hex values that already exist as tokens1,959 uses
--border-default was used on Add money but never defined, so the border never drew1
--fin-up-ring was used on Payment methods but never defined on that page, so the Default badge lost its border1
Network colours (Ethereum, Base, MetaMask) were mixed in with brand colours6
NotificationBell had no usage notes1
36 tokens are never used, including the whole --space-* scale. Pages use raw rem and px36

What changed

  • Pages link the system. Each page now loads ../styles.css. Its :root keeps only values the system doesn't have, or values that really are different. The 217 page overrides that remain are listed in _v21/page-overrides.json.
  • Colours point at tokens. 564 hex values in pages and the UI kit became var(--token) with the same value. Screenshots of all 70 pages and cards match the v2.0 build except Payment methods (see 6).
  • Money-down and error text. --fin-down and --error changed from #ab5770 to #a5536b. That keeps 4.5:1 on every Huma surface. --brand-red stays #ab5770 for brand fills.
  • Missing tokens added. --border-default is now an alias of --border-subtle.
  • Third-party colours have their own file, tokens/third-party.css (--brand-ext-*). WalletPill uses it.
  • NotificationBell has usage notes.

The Unera family

Three systems share one spine: Deep Blue chrome, one grotesk and fixed money colours. Each one then adapts it to its own users.
